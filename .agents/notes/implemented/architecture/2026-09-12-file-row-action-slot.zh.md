# Agent Note: 工作空间文件树的文件行操作插槽

Status: implemented

[English](2026-09-12-file-row-action-slot.md) | 中文

## 问题

工作空间文件树把每个列出的行渲染成封闭控件：打开文件是行上唯一的动作，行区域没有任何扩展点。企业知识库工作台需要在文件行上放置「上传到知识库」操作，未来任何行级功能都会遇到同样的空缺。若把企业逻辑直接写进树包，核心 UI 会与企业业务行为耦合，并把企业维护的改动放进上游持续演进的核心包里。

## 决策

[ui-sidebar-files](../../../../packages/client/ui-sidebar-files/README.zh.md) 持有通用加法插槽 `sidebar.files.entry.action`。`entry-slots.ts` 把它声明为 session 作用域，owner props 为 `{ path, name }`（行的绝对工作空间路径与文件名），files 标签页主体的注册把该键列入自己的 children 表，渲染授权留在树包内。`FilesBody` 在每个文件行的打开控件之后分发该插槽，且仅在文件行分发；目录行、`other` 条目和表头都不分发。无占据者时不渲染任何额外内容，占据者也绝不改变行自身的打开行为。

占据者从自己的包注册。企业工作台经 `ctx.slots.inject` 占据该插槽（id `kb-upload`），注入绑定的 `workspaceFiles.readAll` 回调；全部企业行为——知识库选择、multipart 上传、解析状态提示——都在企业包内的占据者组件里。

插槽刻意保持通用：命名中性、owner props 最小、不含企业词汇，因此核心包的这处 diff 具备向上游贡献的条件。上游合入该插槽后，树包的本地改动即可退役，企业占据者照旧对上游声明注册、无需修改。

## 测试

body 规格测试钉住分发契约：每个文件行且仅文件行分发插槽，携带行的绝对路径与文件名，无占据者时行上不新增任何内容。

## 已考虑的替代方案

**把整个 files 标签页 fork 进企业包。** 复制树的 store、face 与 body 可以不碰核心包，但复制了一个持续演进的组件；上游对树的每次改动都要手工追平，漂移成本高于一个小的已声明插槽。

**把企业上传操作硬编码进 `FilesBody`。** 核心包将导入企业的 API 客户端与对话框，把企业边界朝更糟的方向倒置：这个缝的存在意义正是让树包不含企业概念。

**由企业包在行上叠加控件。** 不经声明插槽、把外来元素定位到树行之上，依赖树的内部布局，上游样式调整时会无声失效，并绕开插槽的声明-授权模型。

## 后果

核心包 diff 为一个新文件加上注册 options 与 body 组件里的少量插入。上游重构 `FilesBody` 可能与这些 hunk 文本冲突；每个 hunk 都可机械重新套用，且插槽无占据者时不改变行为，语义风险为零。任何包都可占据该插槽；只有 ui-sidebar-files 能重新声明或移动渲染点。合并重塑文件树的上游代码时，以本说明为起点：这些 hunk 属于该插槽，把插槽上游化是彻底移除本地核心改动的路径。
